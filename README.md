* Сильно переусложнённая архитектура для подобного проекта. Конечно возможно он будет расширяться, но я этого наверняка
не знаю, поэтому больше исхожу из текущей ситуации. Возможно стоило бы сделать один модуль, а разделение слоёв (контоллер, сервис и прочее)

* Учитывая такие потенциально проблемные моменты как составной первичный ключ, много ко многим и прочее, то я бы лучше
бы заменить маппинг через аннотации, на написанную ручками имплементацию маппера. Это даст более прозрачный,
удобочитаемый код, а следовательно поддерживать его будет легче. При более простых объектах и связях между ними
целесообразнее использовать маппинг аннотациями.
* С учётом текущего задания manyToMany здесь только ради того чтобы он был. Для реальной работы тут стоило бы использовать oneToMany
* Нагрузочные тесты обычно выполняются внешним сервисом, а не помещаются внутрь проекта как юнит тесты.
